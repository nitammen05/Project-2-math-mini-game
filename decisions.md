# Decisions made without being asked

`Spec.md`, `Problem.md` and `CLAUDE.md` didn't settle these, so Claude chose them while
building Math Quest. Each entry gives the choice, the reason for it, and where to change it.

## How the program runs

1. **The "website" is a local web server written in Python.** The spec asks for a
   website, but `CLAUDE.md` says Python only and run from a terminal. `main.py` starts a
   server from Python's standard library (`http.server`), and you play in the browser.
   *Change it in:* `web.py`, `main.py`.
2. **There are no HTML, CSS or JavaScript files.** The pages are built as text inside
   `web.py`, and the styling is a string called `STYLE`. This keeps the program
   "Python only". The page doesn't use JavaScript at all: each answer is a plain form
   submit that reloads the page.
3. **Nothing needs to be installed.** Only the standard library is used.
4. **The server only accepts connections from your own computer** (`127.0.0.1`).
   Other devices, such as your phone, can't connect to it. *Change it in:* the `host`
   argument of `make_server` in `web.py`.
5. **The default port is 8000, and the browser opens automatically.** Three
   command-line options were added: `--port`, `--problems` (use a different problems
   file) and `--no-browser`. *Change it in:* `parse_args` in `main.py`.
6. **The terminal stays quiet while you play.** The server doesn't print a line for
   each page request; it only prints the start-up message. *Change it in:* `log_message`
   in `web.py`.
7. **After you submit an answer, the server redirects you back to the main page.**
   This is called Post/Redirect/Get. It means refreshing the page doesn't submit your
   answer a second time.

## The problems file

8. **The file format is `category | question | answer`.** Lines starting with `#` are
   comments, and blank lines are ignored.
9. **A broken line stops the program.** It prints an error with the line number and
   exits, rather than quietly skipping the line.
10. **The 75 starter problems were generated by a throwaway script** (15 per category,
    random seed 299), and the script wasn't saved. The ranges:
    - addition: 1–50 + 1–50
    - subtraction: never negative, numbers up to 99
    - multiplication: 2–12 × 2–12
    - division: always divides evenly, answers 2–12
    - exponents: squares up to 12², cubes up to 5³, powers of 2 up to 2⁸
11. **Symbols:** `x` for multiply, `/` for divide, `^` for powers.
12. **Answers must be whole numbers.** Text, decimals or a blank answer count as wrong,
    and the opponent attacks you. *Change it in:* `check_answer` in `problems.py`.

## Game design

13. **The name is "Math Quest."**
14. **There are five opponents, in this order:** addition, subtraction,
    multiplication, division, exponents. The spec only says addition is easier than
    multiplication; the rest of the order is Claude's choice.
15. **Opponent names and stats** (in `OPPONENTS` in `game.py`):

    | Opponent | Math | HP | Attack |
    |---|---|---|---|
    | Slime of Sums | addition | 3 | 1 |
    | Goblin of Minus | subtraction | 4 | 2 |
    | Orc of Times | multiplication | 5 | 2 |
    | Troll of Division | division | 6 | 3 |
    | Dragon of Powers | exponents | 7 | 4 |

16. **Combat numbers** (the constants at the top of `game.py`):
    - You have 10 HP.
    - A correct answer deals 1 damage.
    - Every 3rd correct answer in a row is a critical hit that deals 2 damage.
    - A wrong answer resets your streak.
    - Your streak carries over from one opponent to the next.
    - Beating an opponent heals you 3 HP, up to the 10 HP maximum.
17. **Scoring:** 10 points per point of damage you deal, so a critical hit is worth 20.
    You also get a bonus of 50 × the opponent's number (1 to 5) for each opponent you
    defeat.
18. **A wrong answer shows the correct answer,** so you can learn from it.
19. **Problems are shuffled and don't repeat** until every problem in that category has
    been used.
20. **The game is won by beating all five opponents.** There's no endless mode, no
    difficulty setting, and no way to start at a later opponent.
21. **An opponent is skipped if its category has no problems in the file.** If no
    category has problems, the program stops with an error.

## Data and sessions

22. **Each browser gets its own game,** tracked by a cookie.
23. **Nothing is saved to disk.** Games and scores are lost when the server stops, and
    there's no high-score list. Old games stay in memory until the server stops, which
    is fine for one player.

## Look and feel

24. **The page has a dark purple theme,** a green HP bar for you and a red HP bar for
    the opponent, a large question, and an "Attack!" button. The answer box is selected
    automatically, so you can just type.
25. **All text is HTML-escaped** before it's shown. This stops a problem's text from
    breaking the page if it contains characters like `<`.

## Tests and the repository

26. **Tests use `unittest`,** because pytest wasn't installed.
27. **One test checks every answer in `problems.txt`.** It does this by calculating each
    question with Python's `eval`. If you add problems that use new symbols, that test
    needs updating.
28. **The web tests start a real server on a free port** (port 0) and send it requests
    the way a browser would.
29. **`.gitignore` excludes `__pycache__/`,** the folders where Python keeps compiled
    copies of your code.
